# Data checks and chart selection

## Establish the data contract

For UTF-8 CSV, optionally run `python3 <skill>/scripts/profile_csv.py <file.csv> --key <confirmed-id>` (repeat `--key` for a composite key). The read-only JSON report counts blanks, parseable numbers, nonfinite values and duplicates among complete explicitly supplied keys, and binds the report to the input SHA-256. It does not identify sentinel missing values, units, independent units, pairings, or scientific meanings; confirm these from metadata. No key implies no duplicate-key claim. Malformed rows or headers stop the scan.

Locate a candidate in the [V01–V32 research-question index](figure-family-index.md) or run `python3 scripts/figure_routes.py V06` from the skill root. The index includes required evidence and alternatives when the data only support a simpler comparison. [Lookup script](../scripts/figure_routes.py)

Use `python3 scripts/chart_guard.py --list` to see the nine families with implemented evidence checks and their fields. After checking the source data and definitions, express the confirmed facts as JSON booleans. `--suggest facts.json` lists eligible candidates. `CHART facts.json` names any missing conditions for a specified candidate. Choose the view by the question and use a simpler supported comparison when the linkage or decomposition is missing. The [model-output guide](model-output-routing.md) covers joint draws, stage transitions and additive contributions. For a distribution over time or a feature matrix keyed by sample, see the [weighted state field](weighted-state-fields.md) and [sample atlas](sample-atlas.md).

Create a compact variable dictionary with: file/sheet, variable, definition, type, unit, allowed range, missing-value encoding, category order, display precision, analysis role, and transformation. Confirm the observational grain and the fields that uniquely identify a row.

Inspect files, sheet structure, headers and relevant companion methods first; do not rely only on column names or automatic type detection. Record each consequential field as **confirmed** with source, **provisional** hypothesis with its basis, or **missing**. Explicitly distinguish measured observations, simulated/model outputs, fitted summaries and intended predictions. The same numeric column can represent individual measurements, repeated measurements or estimates; apparent matching values do not establish pairing or independent replication.

Recover units, group definitions, measurement/design hierarchy, time order, independent unit, identifiers and interval/test meaning from supplied metadata where possible. If an unknown would change the plot or inference, ask a focused question while completing independent data checks; a simple descriptive preview is permissible only if its actual axes/mappings are supported and its missing design information is disclosed. Do not join rows, connect marks, compute error bars or assert sample size/independence on an unsupported assumption. Preserve ambiguity and mark captions `[待补充]` where needed.

Check at minimum:

- schema and unexpected type coercion;
- duplicate or incomplete keys;
- missing, non-finite, sentinel, and censored values;
- impossible values and unit conflicts;
- category order and labels across files;
- balance, pairing, nesting, repeated measurements, and independent experimental units;
- the exact denominator behind percentages and normalized values;
- outlier/exclusion rules and whether they were defined before inspection;
- transformation, smoothing, interpolation, aggregation, and random seeds.

Do not delete unusual observations for visual convenience. If an analysis excludes data, retain an auditable record and explain it in methods/legend as appropriate.

## Match data structures to genome and protein composite views

When the supplied data and question match a row below, automatically consider its first choice during chart selection and record the decision in the existing project notes. Match by confirmed variable meanings, observation grain, keys and question, not column names alone. A row is a candidate, not a request to produce every panel. If required inputs are missing, mark them `missing`, use a supported simpler view where useful, and ask for information that changes the inference. Do not run an analysis, infer a mechanism, or create a mapping merely because a familiar chart could display it. For the visual evidence and screenshot limitations see [the genome/protein reference review](reference-observations-2026-11-02-genome-protein-composites.md).

| Confirmed structure and question | Candidate view | Conditions and alternatives |
|---|---|---|
| Object IDs with existing 2-D embedding coordinates and categorical or continuous metadata; show organization or provenance | Keyed scatter embedding, optionally recoloured in a second panel using the same coordinates | Verify one-to-one joins, coordinate provenance and coverage; label colour meaning and manage overplotting. Without valid coordinates, use supported summaries or separately justify a computed embedding; apparent distances do not prove biological similarity. |
| Cluster ID, object counts and category-specific counts; compare cluster size and composition | Scatter of cluster size against category fraction, optionally ranked stacked counts | Define denominator, exclusions and cluster assignment; use log count scale only with zero handling. If counts are absent, do not infer them from proportions. |
| Matched entities with two continuous frequencies or scores; compare sources or co-occurrence | Scatter with equality line for comparable units, or association scatter for different metrics | Join by verified ID, define population, units and transformations; log axes require explicit zero handling. Correlation needs an appropriate paired sample and does not establish causation. |
| Two collections of numeric lengths or occurrence counts; compare distributions | Shared-axis histogram or density panels | Verify comparable units, sampling and normalization; harmonize bins for histograms, disclose density bandwidth and sample counts. Use a dot/interval summary when distribution data are unavailable. |
| Known nodes and edges, optional weights and categories; compare relationship structure | Readable network or adjacency matrix; chord diagram only for a manageable, meaningful set of links | Verify direction, edge definition, weights, filtering and missing edges. Prefer a matrix or ranked edge table when chord labels or overlaps obscure comparisons. |
| Experiment/condition, time, response and replicate or sample ID; compare dynamics | Time-course curves or aligned small multiples | Distinguish observed traces, model summaries and supported intervals; connect observations only when IDs justify it. Without valid time/replicate identity, use unconnected points or mark the ambiguity. |
| Row and column IDs with identity, conservation or error values; examine pairwise or positional patterns | Heatmap with explicitly labelled metric and scale | Verify matrix alignment, units, missingness, ordering and bounds; keep distinct metrics on separate scales. Use a table or dot plot when a small matrix is clearer. |
| Sequence ID, length and validated domain start/end coordinates; compare architectures | Aligned domain tracks, optionally alongside supported structural comparisons | Check coordinate convention, boundaries, IDs and sequence lengths; label source/method and computational versus experimentally verified status. Missing coordinates cannot be reconstructed from a picture. |
| Independent groups and per-unit observations or supplied estimates with interval definitions; compare frequency or response | Points with appropriate summary/interval, or grouped bars for defined aggregate counts | Establish denominator, independent unit and interval type; do not invent replicates or uncertainty. Bars start at zero; use distributions when individual data carry the comparison. |
| Ordered stages and documented entities, dependencies and criteria; explain a workflow | Editable process diagram with named arrows and stages | A diagram documents the supplied process, not an analysis result; mark hypothetical steps and avoid adding unverified thresholds. |

For multi-view requests, use only complementary views supported by the available data and claim. Keep candidate-specific eligibility and missing inputs visible in the selection note; create and inspect saved R in RStudio or a native Origin project under the main workflow. These mappings guide the assistant's decisions and do not constitute an autonomous classifier or guarantee that unfamiliar datasets will be interpreted correctly.

## Compare encodings before producing figures

For each substantive research question, consider two or three **plausible** encodings when they differ meaningfully, using the supplied design and the table above; for a straightforward or explicitly specified plot, record the one appropriate option without forcing alternatives. Compare what each shows or hides: directness of the comparison, pairing/independence, data and uncertainty support, amount of occlusion, valid scale/units, readability at final size and whether it adds evidence already shown elsewhere. Use the requested style unless it conflicts with these requirements; explain a conflict and offer a supported alternative.

Record in the project's existing notes the question, selected encoding and evidence role, one meaningful rejected or conditional alternative and why, and remaining missing inputs. This is a decision note, not a requirement to draw every candidate or create another manifest. Select different chart types when they answer different questions, not for novelty; preserve consistent group encodings across related views. If multiple views only repeat one message, retain the clearest view unless the user wants the alternatives.

For example, time × group × measurement can be shown as connected within-unit trajectories only when row-level IDs and repeated-measure identity support the connections. For distinct samples at each time, consider individual points with a distribution or a group summary; derive an interval only from a supplied or justified design/method. If pairing or independence is unknown, label it missing rather than infer it from timestamps or group names.

Avoid dual y-axes unless the physical relationship is fixed and unambiguous. Bars encoding length should start at zero. Point, line and interval plots may use a focused range when it is explicit and does not hide relevant comparisons; retain meaningful null/reference lines and explain omitted context. Do not silently discard observations with scale limits or use breaks to exaggerate differences. For log axes, label the scale and handle zero/negative values transparently. Nonuniform heatmap coordinates require explicit numeric cell geometry or an explicitly discrete axis; do not imply equal numerical spacing with equal-width cells.

## Heatmap decisions

State whether color represents raw values, row/column z-scores, fold changes, or another transform. Set and record the center, limits, out-of-range behavior, missing-value color, ordering, distance metric, linkage, and any annotation mapping. Use a perceptually ordered sequential palette for magnitude and a balanced diverging palette only when the center is scientifically meaningful.
