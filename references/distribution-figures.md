# Comparing distributions with informative detail

Read for grouped raw observations, violin/half-violin, raincloud, box or mean-and-spread plots. Choose the display from the question and data contract; the observations motivating these rules are in [the 2026-10-30 image review](reference-observations-2026-10-30-distribution-detail.md), not a mandatory layout or colour scheme.

## Encode the actual statistical objects

- Identify the observational and independent experimental unit, group membership, exclusions, missing values and any paired/repeated structure before choosing a display. Use stable keyed colours, shapes and order across related panels. For paired observations, connect only verified matches; independently sampled groups should not imply pairs.
- Individual marks show supplied observations. If marks overlap, use a recorded seed for jitter or a declared beeswarm/binning rule; move points only along the categorical axis, never alter values to separate marks. Check raw counts versus plotted inputs and disclose overplotting or aggregation; a dense scatter need not visually show every observation.
- A violin is a kernel density estimate, not a frequency bar or a sample-size display. Record bandwidth/kernel, boundary treatment, trimming/support and width normalization; for comparable density shapes use a consistent, justified computation and explain whether area/width encodes group size. Do not infer multimodality or tails solely from a smoothed silhouette; compare with observations and sensitivity to bandwidth. For small samples or highly discrete data, prefer identifiable raw points or another suitable display.
- Define box centre, quartiles and whisker/outlier convention from the method actually used. Distinguish mean ± SD (sample spread) from SE, confidence/credible or predictive intervals (different quantities); name the marker and every interval in the caption. A group SD is not an effect estimate or proof of significance.
- If bar height shows a mean, preserve a zero baseline and avoid making the filled bar hide the distribution; consider points plus an interval or a box/violin if the distribution is central. Keep precision consistent with measurement and analysis, and report the group sample counts with the proper unit.

## Use space for supported information

Treat the user's preference for informative whitespace as a design consideration: examine whether unoccupied space limits the message or is needed for scales, comparison and readability. It need not be filled. When a meaningful feature is supported, choose a small number of high-value labels or a clearly linked detail inset and document the selection rule; otherwise preserve the space.

- Identify candidates from the actual data and question: a predefined threshold crossing, a verified observation relevant to a documented condition, a labelled quantile/median, a dense overlap region, or a scientifically defined range. A visual extreme is not automatically an error, diagnosis, important case or outlier. If a case is selected after viewing, disclose that it is descriptive and how it was selected; do not present it as a representative or confirmatory result without justification.
- Put concise labels, matching-colour leaders or an outline near the selected observation, reserving room for axis and data; use `ggrepel` when necessary and available. Trace each label to a stable source ID/value and explain its meaning. Do not expose sensitive personal IDs in a deliverable; use anonymous codes or aggregated annotations. Avoid obscuring other observations, hiding the tail, or giving selected cases unjustified visual dominance.
- Use a zoom only if it resolves an actual overlap or locally important feature. Derive the selection from the same source rows and transformations as the main plot, identify the selected region and disclose the inset axis range and changed scale. Keep the full distribution and all observations visible in the parent view. Preserve or explicitly explain any common axis across other comparable panels. No opaque mask may hide data merely to improve appearance.
- Prefer direct summary information when it helps interpretation: definition of n, median and quartiles, a documented reference line, or an effect estimate with its correctly named uncertainty when already supported. Never add a numeric statistic, p-value, diagnostic claim or mechanism to occupy space.

## Composition, implementation and checks

- Give raw observations, density, summary and optional inset separate roles; space them so the silhouette does not engulf the scatter or obscure the box/interval. A half-density, separate points and box (raincloud) can help at sufficient width; if components collide at final size, reduce layers, split a view or move supporting detail to the caption.
- Set and actually wire project configuration for group names/order, palette/shape, dimensions, spacing, density method/bandwidth/normalization, jitter seed, point opacity/size, summary definitions, highlight ID/selection reason, inset extent, axis limits and export settings. These are proposed project-specific settings, not implemented fields in every bundled template. Use saved R code in RStudio, `ggplot2` and existing packages where suitable; install nothing merely to imitate the reference.
- Inspect the complete rendered figure, each panel and any inset at final placed size. Cross-check n, IDs, values, displayed group summaries and interval meanings against the input; distinguish plotted input counts from visibly separable points. Inspect small marks/outline/leader contrast, label collisions and the actual grayscale and colour-vision views. Repair saved code and rerender; see [the unified QA workflow](rendered-qa.md).
- A 3D scatter can conceal observations or distort apparent separation through the view angle. Use it only when three-way structure is material and the static view is defensible; set labels/viewpoint and check occlusion, and consider aligned 2D scatter/facets or an authorised interactive companion. Apparent clustering alone does not establish prediction or causality.

## Percentile summaries across indicators

For heterogeneous objects measured on several outcomes, consider aligned horizontal percentile spans with separately keyed median/mean marks when between-object variation is the question and validated summaries exist. Name the quantiles and weighting; these spans are not confidence intervals and need not start at zero. Preserve a common item order across indicator columns, label each unit and functional-unit group, and do not compare lengths across independently scaled axes. Keep exact values in a compact adjacent table only where needed. Full endpoints or explicit clipping indicators must remain available. See [Science Figure 1 and its transfer limits](reference-observations-2026-11-04-nature-science-uncertainty.md).
